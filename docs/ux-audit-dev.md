# blizu: альтернативный UI/UX в ветке dev

Дата: 5 ноября 2026 года. Исходная версия: `989c6a0`.

Цель — превратить презентационную главную в удобный инструмент повседневного выбора: найти услугу, сравнить условия, сохранить подходящее и создать понятную заявку. Это экспертная проверка интерфейса и реализации. Исследование с реальными пользователями ещё не проводилось.

## Основания для решений

- [WCAG 2.2: контраст](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): ориентир 4,5:1 для обычного текста и 3:1 для крупного.
- [WCAG 2.2: размер целей](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): минимум 24×24 CSS px либо предусмотренные стандартом исключения; для основных действий выбран ориентир 44 px.
- [NN/g: полезные фильтры](https://www.nngroup.com/articles/filter-categories-values/): критерии должны соответствовать задаче, быть понятными и предсказуемыми.

Следование этим ориентирам само по себе не означает сертифицированное соответствие WCAG или подтверждённый рост конверсии.

## Найденные проблемы и изменения

| Приоритет | Наблюдение в исходной версии | Решение в dev |
| --- | --- | --- |
| P1 | Большая презентационная область и анимированное появление текста отодвигали поиск и понимание сервиса | Типографический первый экран с поиском; фотокарусель убрана |
| P1 | Вторичный цвет `#87908b` на `#fbfcf9` даёт около 3,19:1 | Вторичный текст `#6d6a64` на `#f7f5f0` — около 4,95:1; белый текст кнопки на `#28646d` — около 6,70:1 |
| P1 | Не хватало критериев выбора и видимых применённых фильтров | Цена, рейтинг, отметка профиля, удаляемые фильтры и число результатов |
| P1 | Поиск города не воспроизводился через ссылку | Город, запрос, категория, фильтры, сортировка и страница отражаются в URL |
| P1 | Сердечко для гостя заканчивалось предложением войти | Гостевое избранное на устройстве; перенос в аккаунт отдельным действием |
| P1 | Закрытие формы уничтожало введённый текст | Черновик в sessionStorage, отдельно для аккаунта и контекста предложения; очистка после успешной публикации |
| P1 | «Обсудить задачу» могло восприниматься как личный контакт с выбранным мастером | «Создать заявку» с объяснением открытых откликов и следующего шага |
| P2 | Варианты приходилось запоминать или открывать в разных вкладках | Сравнение до трёх предложений: цена и единица, город, категория, исполнитель, оценки |
| P2 | Не было удобного возвращения к просмотренному | Недавние поиски и просмотренные предложения |
| P2 | Мобильная навигация зависела от меню; минимальная ширина была 360 px | Нижняя навигация, адаптация CSS от 320 px, отдельное окно фильтров |
| P2 | Не у всех переключателей было доступное состояние; заголовок диалога не был связан с dialog | `aria-pressed`, именованные диалоги с уникальными идентификаторами, skip-link |
| P2 | Общий React-бандл зависел от чанка Three.js | Явное разделение React и WebGL; проверка поддержки WebGL до импорта сцены |

Контраст рассчитан по формуле относительной яркости sRGB. Значения относятся к указанным парам цветов, а не ко всем пикселям и состояниям интерфейса.

## Новое визуальное направление

В текущем варианте: песочная основа `#f7f5f0`, графитовый текст `#282826`, петрольный акцент `#28646d` и мягкий оттенок выделения `#e3eff0`. Заголовки используют локальную Lora с настоящим курсивом и кириллицей; рабочие элементы — локальный Manrope. Lora подключена в WOFF2, с font-display: swap и предварительной загрузкой обычного кириллического начертания; лицензия OFL включена в репозиторий. Первый экран центрирован вокруг поиска и не содержит слайдов или декоративных фото. Фото оставлены в карточках, где помогают оценить предложение. Внешних запросов за шрифтами во время работы приложения нет.

По отдельному запросу 6 ноября добавлена необязательная декоративная R3F-сцена позади поиска. Она рисует медленный световой перелив по краям, сохраняет композицию и доступность HTML, загружается с задержкой и отключается при reduced motion / Save Data. Когда первый экран или вкладка не видны, цикл отрисовки останавливается. Фактический вид в браузере этой сессией не проверен.

Акцент применяется к основному действию и выбранным состояниям. Рамки и разделители тонкие; тени и масштабирование карточек сведены к минимуму. Мобильные категории расположены в горизонтальном списке. Стили прежнего фотоэкрана больше не подключаются к приложению.

Главная построена вокруг последовательности «поиск → категория → выбор → сравнение → заявка». Под каталогом находятся открытые заявки, недавно просмотренное и объяснение процесса. На рабочих страницах применены общие токены, формы, карточки, кнопки и статусы.

Полупрозрачные поверхности используют общий CSS-класс `.glass-panel`: поиск, форма доставки, панель профиля и фильтры заказов. Шапка также полупрозрачна. Для видимости эффекта под панелями расположены спокойные цветовые подложки; размытие, светлые края и внутренний блик создают глубину. Основные карточки с данными остаются белыми. Если backdrop-filter не поддерживается, панели получают непрозрачный фон.

Доставка начинается с ссылки и страны отправления. Эти данные переносятся через авторизацию в форму заявки; на этом этапе публикации ещё нет. Стоимость и срок появляются в откликах логистов. Визуальная 3D-посылка приведена к новой палитре, движущиеся точки убраны.

Личный кабинет показывает профиль, реальные показатели и последние заказы. На телефоне контакты доступны по кнопке «Данные профиля». Сохранены предложения исполнителя и споры арбитра. Заказы вынесены в `/orders`: поиск по названию, участникам и городу, фильтры типа и состояния, сортировка и сброс пустой выдачи. Настройки списка отражаются в URL. Фильтрация выполняется на клиенте по всем заказам, доступным пользователю из `/dashboard`; при росте объёма нужна серверная пагинация.

Основные файлы: `src/DiscoverPage.tsx`, `src/DeliveryPage.tsx`, `src/WorkspacePages.tsx`, `src/refined.css`, `src/marketplace.css`, `src/market-state.tsx`, `src/components/CompareTray.tsx`. Существующая бизнес-логика заказов, откликов, чатов, споров и доставки используется в новом интерфейсе. Новых переменных окружения и изменений контейнерного развёртывания нет.

### Семь визуальных улучшений

1. Типографика: Lora для заголовков, Manrope для действий и данных. В переработанных стилях размеры подписей в px подняты как минимум до 12; мобильные поля ввода используют 16 px. Маленькие метрики кабинета меняют компоновку на узких экранах.
2. Главная: короче описание, компактнее первый экран и вспомогательные действия; поиск остаётся главным действием. Категории и каталог образуют следующие уровни иерархии.
3. Карточки: фотографии 4:3, одинаковое кадрирование и спокойная обработка услуг; для товаров фильтр цвета отключён. Название → цена → описание → исполнитель с рейтингом. Одна подпись категории на фото, кнопка сохранения 44 px; изображения не двигаются при наведении.
4. Стекло: общие параметры прозрачности, размытия и света. Подложки, светлый верхний и левый край, тень и фокус согласованы; сохранён непрозрачный fallback.
5. Заказы: три этапа услуги и пять этапов доставки. Компактная схема в списке, полная — в заказе; спор не изображается как успешное прохождение обычных этапов. Следующие действия в кабинете основаны на реальных заказах, откликах и роли. Общий помощник действий используется также в карточке заказа; серверные права остаются прежними.
6. Айдентика: собственные SVG-иллюстрации для поиска, заказов, избранного, переписки и маршрута. Знак blizu используется в уведомлениях и блоке действий. Успешные и ошибочные сообщения оформлены различимо.
7. Движение: переходы 180 мс для выбора категории, сохранения, сравнения, панелей, FAQ и диалогов; уведомления можно закрыть. Закрытые ответы FAQ имеют aria-hidden и inert. При prefers-reduced-motion анимации и переходы отключаются; существующая R3F-сцена также учитывает эту настройку.

## Функциональность и сохранение данных

- Фильтрация выполняется API до пагинации. Ответ содержит актуальный `total`; порядок страниц стабилизирован по ID.
- Сравнение сохраняет выбор при переходах внутри приложения, максимум три варианта. Разные единицы стоимости показаны явно.
- Гостевое избранное и недавнее хранятся в браузере. Повреждённые записи игнорируются. Эти данные не синхронизируются с аккаунтом до нажатия кнопки переноса.
- Черновики формы живут в текущей вкладке, привязаны к ID аккаунта и контексту услуги. Пароли и поля авторизации в черновики не попадают. Черновик не является опубликованной заявкой.
- Ошибочный диапазон цены объясняется до запроса. Пустой результат предлагает ослабить фильтры или создать заявку.
- Список и плитка переключаются; выбранный вид сохраняется на устройстве.
- Нет вымышленных обещаний о времени ответа, доступности мастера или количестве клиентов. Демонстрационный каталог отмечен явно.

## Проверка

Новые интеграционные UI-тесты используют React в JSDOM и настоящий Express API с отдельной SQLite-базой. Проверяются поиск по готовой ссылке, диапазон цены, история поиска, гостевое избранное, сравнение, недавние просмотры, восстановление и публикация черновика, перенос избранного в аккаунт. Отдельный API-тест проверяет фильтры, сортировку, пагинацию и ошибки валидации.

Команды:

Итоговый запуск: production-сборка успешна, **23/23 теста пройдено** — 9 API и 14 UI/API. Добавлены проверки переноса ссылки доставки через авторизацию, фильтров и сортировки заказов, личного кабинета исполнителя и арбитра, ограничения гостевого доступа, реального подтверждения получения с обновлением этапа, следующих действий, доступного раскрытия FAQ и закрытия уведомления без потери избранного. В собранном `index.html` отсутствует предварительная загрузка Three.js; WebGL вынесен из загрузки основного React-интерфейса.

```bash
npm run build
npm test
npm run test:ux
npm run test:api
```

Визуальная проверка реального браузера в этой сессии недоступна: оба штатных инструмента подключения завершаются ошибкой `failed to write kernel assets`. JSDOM не проверяет переносы строк, геометрию, реальный фокус нативного dialog или работу GPU. Новых скриншотов поэтому нет; старые снимки в docs относятся к предыдущему дизайну.

Перед выпуском нужны проверки в реальном браузере на 320/390/768/1280 px, клавиатура и screen reader, зум 200%, фокус диалогов и reduced motion. После этого — короткие сессии с пользователями: найти мастера в своём городе, сравнить варианты и восстановить незавершённую заявку.

## Следующие продуктовые шаги

1. Проверить сценарии на 5–8 представителях местного сообщества; измерять успешное завершение задачи и места затруднений.
2. Проверить доверие: объяснение отметки профиля, подтверждённые отзывы и процесс проверки исполнителей.
3. Завершить локализацию рабочих сценариев и восстановление доступа перед широким запуском.
4. Добавлять новые функции по наблюдаемой потребности: собственные фото исполнителей, доступность по времени и адресные уведомления.

Локальный запуск: `npm ci`, затем `npm run dev`, адрес `http://127.0.0.1:5173/`. Ветка dev содержит альтернативную реализацию; сравнение с исходной возможно через main.
