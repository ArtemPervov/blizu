# ИИ-помощник Blizu

В Blizu уже есть первый этап интеграции с Ollama. После включения `LLM_ENABLED` пользователи могут войти в аккаунт и открыть «ИИ-помощник» на сайте или по адресу `/assistant`. Чат отвечает на вопросы о Blizu. Поиск с открытием страниц и создание объявлений описаны ниже как следующие этапы.

## Ollama уже запущена

Этот раздел подходит, если вы уже создали сеть `blizu_llm` (тип `bridge`) и загрузили модель. `inference` — имя, под которым файл Compose стека Blizu ссылается на эту сеть.

1. В Portainer откройте **Networks → blizu_llm** и проверьте, что к сети подключён контейнер Ollama. В примере ниже он имеет сетевой алиас `blizu-ollama`. Если в стеке Ollama сервис называется `ollama` и алиас не задан, используйте `ollama` как имя хоста.
2. Для стека из Git откройте **Stacks → blizu → Edit stack settings**. В **Additional paths → Add file** укажите `docker-compose.ollama.yml`. Он дополняет текущий **Compose path** и подключает только `api` к уже существующей сети `blizu_llm`. Сохраните настройки и выполните **Pull and redeploy**. [Дополнительные Compose-файлы в Portainer](https://docs.portainer.io/user/docker/stacks/add#option-3-git-repository) · [Настройки существующего стека](https://docs.portainer.io/user/docker/stacks/edit#edit-stack-settings)

   Для запуска через CLI передайте [сетевое дополнение](../docker-compose.ollama.yml) вторым файлом после основного Compose.

   ```sh
   docker compose -f docker-compose.yml -f docker-compose.ollama.yml up -d --build
   ```

3. В **Containers → контейнер Blizu API → Console** запустите `/bin/sh` и выполните команду. Если у вас имя хоста `ollama`, замените `blizu-ollama` в команде.

   ```sh
   node -e 'fetch("http://blizu-ollama:11434/api/tags", {signal: AbortSignal.timeout(5000)}).then(async r => { if (!r.ok) throw Error(String(r.status)); console.log((await r.json()).models.map(m => m.name)) }).catch(e => { console.error(e); process.exitCode = 1 })'
   ```

   В списке должна появиться `qwen3:8b`. Ошибка `ENOTFOUND` означает, что API не разрешает указанное имя контейнера. Сверьте алиас и проверьте, что **оба** контейнера отображаются в сети `blizu_llm`. Пустой список моделей означает, что Ollama доступна, но модель ещё нужно загрузить в этом контейнере командой `ollama pull qwen3:8b`. [Проверка списка моделей](https://docs.ollama.com/api/tags)

4. Для чата обновите оба образа Blizu, `api` и `web`, из текущих исходников. Внесите переменные ниже в **Environment variables** стека. В [Compose для Portainer](../docker-compose.portainer.yml) они уже передаются в контейнер `api`. Если используете свой Compose, перенесите также строки `LLM_*` из его блока `environment`.

   ```dotenv
   LLM_ENABLED=true
   LLM_BASE_URL=http://blizu-ollama:11434
   LLM_MODEL=qwen3:8b
   LLM_TIMEOUT_MS=45000
   ```

   После обновления зайдите в Blizu и задайте вопрос «Где посмотреть мои заказы?». Тот же маршрут `/api/` обслуживает чат через существующие Nginx и Express. Для локального Node-процесса с Ollama на том же ПК укажите `LLM_BASE_URL=http://127.0.0.1:11434`. [Настройка Nginx Blizu](../deploy/nginx.conf)

## Как это будет работать

| Пользователь пишет                                                             | Что делает Blizu                                                                                                                                                                               |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| «Где посмотреть мои заказы?»                                                   | Отвечает по справке Blizu и предлагает «Мои заказы». По команде «Открой мои заказы» переходит на `/orders`, где действуют обычные правила входа.                                               |
| «Найди чистку кондиционера в Будве до 50 € и открой»                           | Ищет в актуальном каталоге с фильтрами города и цены. Открывает карточку, если найдено одно подходящее предложение, или каталог с применёнными фильтрами, если подходящих вариантов несколько. |
| «Открой самый дешёвый из найденных»                                            | Открывает конкретную карточку из результатов по подтверждённой цене. Если у подходящих предложений цена неизвестна, сообщает об этом.                                                          |
| «Размести объявление: продаю велосипед в Баре за 130 €, рама M, есть царапины» | Заполняет черновик с заголовком, описанием, категорией, городом и ценой. После нажатия «Опубликовать» размещает объявление от имени пользователя и открывает карточку.                         |

React отправляет сообщение в Express по тому же адресу, с которого открыта страница Blizu. Express обращается к Ollama, проверяет предложенные моделью действия, выполняет поиск или готовит черновик и возвращает текст вместе с типизированным действием. React использует обычную навигацию сайта, поэтому переход сохраняет историю браузера. [Вызов функций в Ollama](https://docs.ollama.com/capabilities/tool-calling)

## 1. Запустить модель

Начните с `qwen3:8b`, которая поддерживает вызов функций. Для сервера с ограниченными ресурсами попробуйте `qwen3:4b` и сравните точность поиска и заполнения полей на русском, английском и черногорском. Размер файла модели на диске составляет около 5,2 ГБ для 8B и 2,5 ГБ для 4B. Для инференса нужна дополнительная оперативная память или VRAM. [Qwen3 8B](https://ollama.com/library/qwen3:8b) · [Qwen3 4B](https://ollama.com/library/qwen3:4b)

1. На том же Docker-хосте, где находится Blizu, создайте сеть `blizu_llm` с драйвером `bridge` через **Networks → Add network** в Portainer.
2. Откройте **Stacks → Add stack → Web editor** и создайте отдельный стек `blizu-llm` с этим Compose. В примере выбран CPU-вариант. Для регулярных обновлений закрепите протестированную версию образа или его digest. [Стек в Portainer](https://docs.portainer.io/user/docker/stacks/add) · [Ollama на Docker и GPU](https://docs.ollama.com/docker)

   ```yaml
   services:
     ollama:
       image: ollama/ollama:latest
       restart: unless-stopped
       environment:
         OLLAMA_HOST: "0.0.0.0:11434"
         OLLAMA_NO_CLOUD: "1"
       volumes:
         - ollama_models:/root/.ollama
       networks:
         inference:
           aliases:
             - blizu-ollama
   volumes:
     ollama_models:
   networks:
     inference:
       external: true
       name: blizu_llm
   ```

3. В **Containers → контейнер Ollama → Console** откройте `/bin/sh`. Загрузите модель и проверьте ответ. Дождитесь загрузки модели перед подключением чата. [Команды Ollama](https://docs.ollama.com/docker)

   ```sh
   ollama pull qwen3:8b
   ollama list
   ollama run qwen3:8b "Ответь на русском одним предложением. Что ты умеешь?"
   ```

4. Подключите сеть к Blizu и проверьте список моделей в консоли API по шагам из раздела [«Ollama уже запущена»](#ollama-уже-запущена). Порт `11434` доступен внутри Docker-сети. Nginx Proxy Manager направляет браузер на `blizu-web:8080`, а Nginx проксирует `/api/` к Express. [Сети Docker Compose](https://docs.docker.com/compose/how-tos/networking/) · [Nginx Blizu](../deploy/nginx.conf)

   ```sh
   node -e 'fetch("http://blizu-ollama:11434/api/tags").then(async r => { if (!r.ok) throw Error(String(r.status)); console.log((await r.json()).models.map(m => m.name)) }).catch(e => { console.error(e); process.exitCode = 1 })'
   ```

5. После деплоя новой версии задайте значения в **Stacks → blizu → Environment variables**. При локальной разработке с Ollama на том же ПК используйте `LLM_BASE_URL=http://127.0.0.1:11434` в `.env`. [Настройки API](../server/index.ts) · [Compose для Portainer](../docker-compose.portainer.yml)

   ```dotenv
   LLM_ENABLED=false
   LLM_BASE_URL=http://blizu-ollama:11434
   LLM_MODEL=qwen3:8b
   LLM_TIMEOUT_MS=45000
   ```

   `LLM_ENABLED` включает чат и его API. Выставьте `true` в тестовом окружении после сборки. `LLM_TIMEOUT_MS` задаёт время ожидания ответа. В текущем Nginx у API установлен `proxy_read_timeout 60s`. Если на CPU холодный старт не укладывается в ожидание, измерьте время с 4B и с прогретой моделью. [Параметры Ollama Chat API](https://docs.ollama.com/api/chat)

## 2. Добавить поиск и действия в чате

**Сервер.** Для следующего этапа расширьте `POST /api/assistant/chat` идентификатором диалога и инструментами из таблицы ниже. Текущий маршрут уже проверяет сессию, язык, сообщение и ограниченную историю через Zod и обращается к `POST /api/chat` Ollama. Сервер будет передавать список разрешённых инструментов и результаты их вызовов. Историю и найденные ID привязывайте к конкретному диалогу. Ограничьте число вызовов инструментов за один ответ. [Ollama Chat API](https://docs.ollama.com/api/chat)

| Инструмент              | Как выполнить в Blizu                                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_help`              | Найти в справке статью и вернуть её текст с разрешённым идентификатором страницы. Например, `orders` соответствует `/orders`, `order_help` — `/order-help`.                                               |
| `search_listings`       | Проверить аргументы, затем использовать ту же серверную функцию поиска, что и у `GET /api/listings`. Вернуть несколько актуальных карточек с ID, названием, городом, ценой и признаком, что цена указана. |
| `open_listing`          | Принять ID из недавних результатов этого диалога. Перепроверить публичную видимость, затем вернуть действие `{ "type": "open_listing", "id": "…" }`.                                                      |
| `prepare_listing_draft` | Собрать поля будущего объявления и вернуть черновик для проверки. При нехватке цены, города или другой обязательной информации задать один конкретный вопрос.                                             |

**Поиск.** Вынесите поиск из [серверного обработчика](../server/app.ts) в общую функцию. Сохраняйте действующие ограничения видимости и сортировку. Передавайте отдельно `q`, `category`, `cities`, `maxPrice` и `sort`, если они нужны. Например, для запроса «чистка кондиционера в Будве до 50 €» нормализуйте город до `Будва` и ищите по короткому термину `кондиционер`. Текущий `q` ищет подстроку, поэтому при отсутствии результатов имеет смысл попробовать близкий термин, сохранив город и бюджет. Для «самого дешёвого» используйте `sort=price` и выбирайте из результатов с указанной ценой. [Каталог и его параметры](../src/DiscoverPage.tsx) · [Справочники городов и категорий](../shared/types.ts)

**Открытие страниц.** В React обрабатывайте только известные типы действий. Карточка открывается через `navigate("/listings/" + encodeURIComponent(id))`. Для каталога соберите адрес `/?…#catalog` посредством `URLSearchParams`, используя те же параметры, что при поиске. Открывайте страницу автоматически по просьбе пользователя. Обычный запрос «Найди» показывает карточки в чате с кнопками перехода. Для разделов справки сопоставляйте идентификаторы с фиксированными маршрутами в коде. [Маршруты Blizu](../src/App.tsx)

**Справка.** Начните с небольшой базы знаний в репозитории. Для каждой статьи храните вопрос, ответ, язык, идентификатор раздела и дату проверки. Возьмите сценарии «опубликовать объявление», «написать автору», «найти мои заказы», «открыть спор», «пожаловаться на объявление». Передавайте модели только подходящие статьи и текущий язык. Когда справка вырастет, можно добавить семантический поиск по её фрагментам (RAG). Справку обновляйте вместе с приложением, а объявления запрашивайте из живого каталога. На старте достаточно готовой модели, этих материалов и инструментов.

## 3. Публиковать от имени пользователя

1. Применяйте к черновику ту же схему, что у текущего `POST /api/listings`. Нужны заголовок, описание, категория, город, положительная цена и единица цены. Категорию и город выбирайте из действующих справочников. Для товара единица может быть «шт.», для услуги — «выезд» или «сеанс», после согласования с пользователем. Отображайте выбранную обложку. Текущий маршрут создания принимает предустановленную обложку, загрузка фото владельцем требует отдельного расширения. [Схема публикации](../server/app.ts) · [Форма объявления](../src/forms.tsx)
2. Покажите черновик прямо в чате с действиями «Изменить» и «Опубликовать». Попросите войти, если сессии ещё нет. Публичные Telegram и Viber добавляйте по явному выбору пользователя с указанием, что контакты увидят посетители объявления. Учитывайте настройку видимости контактов профиля в предпросмотре.
3. Кнопка «Опубликовать» вызывает отдельный `POST /api/assistant/drafts/:id/publish`. Express берёт автора из `req.user` и выполняет те же проверки роли и полей, что ручная форма. Вынесите общую валидацию и создание объявления из существующего маршрута, чтобы ручная и автоматическая публикация использовали один код. Модель формирует черновик, публикацию запускает кнопка в интерфейсе. [Сессия и роли](../server/app.ts) · [Модель ролей](../shared/types.ts)
4. Храните черновик с ID владельца, сроком действия и ID созданного объявления. Записывайте объявление и отмечайте черновик опубликованным в одной транзакции SQLite. При двойном нажатии или повторе после сетевой ошибки возвращайте тот же ID. После подтверждённого успеха обновите кэш каталога и откройте `/listings/:id`.

Ограничьте модель набором функций с проверяемыми аргументами. Текст объявлений и импортированных постов используйте как данные. Сессия, полномочия и решение о записи остаются в Express. Cookie, пароли, закрытые диалоги и контакты профиля остаются за пределами контекста модели. В логах достаточно ID запроса, времени, имени инструмента и результата операции.

## 4. Порядок запуска и проверка

1. **Помощь.** Подключить Ollama, собрать статьи и проверить вопросы на трёх языках. На вопрос вне справки помощник сообщает, что информации недостаточно, и предлагает подходящий раздел.
2. **Поиск.** Проверить город и бюджет, пустую выдачу, несколько совпадений, поиск английскими и черногорскими словами и переход к карточке. Скрытое модератором объявление не появляется в результатах и не открывается по старому ID. Убедиться, что после перехода с мобильного можно вернуться к диалогу.
3. **Публикация.** Пройти сценарии товара и услуги под обычным аккаунтом. Проверить недостающую цену, редактирование, отмену, повтор запроса и попытку подтвердить чужой черновик. Одно подтверждение создаёт ровно одно объявление от текущего пользователя.
4. **Пилот.** Измерить задержку на холодном и прогретом запуске и при нескольких одновременных обращениях. Проверить сообщения об ошибках при остановленной модели. После проверки включить чат через `LLM_ENABLED=true`.
