# blizu — ваши люди в Черногории

Полноценный MVP по двум исходным документам: React + TypeScript + React Three Fiber, API на Express + TypeScript, SQLite в режиме WAL. Данные сохраняются на диске. Рабочее название и визуальная айдентика — **blizu** («рядом»).

[Внешний вид](docs/preview-full.jpg) · [Мобильная версия](docs/preview-mobile.jpg) · [Результаты проверки](docs/verification.md)

Все переменные для Portainer с обязательными значениями и настройками по умолчанию: [docs/environment.md](docs/environment.md).

## Запуск локально

Нужны Node.js **22.18+** и npm. На Windows с ограниченной политикой PowerShell используйте `npm.cmd` вместо `npm`.

```bash
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. Vite проксирует `/api` на порт 3001. Без `.env` локально включены демонстрационные данные. В окне входа доступны аккаунты «Заказчик», «Мастер», «Арбитр». Вымышленные предложения и рейтинги отмечены в подвале. Не переносите демонстрационную базу в production: при выключенном демо-режиме такой запуск отклоняется. Демо-вход создаёт настоящую сессию, поэтому изменения сохраняются.

Чтобы начать с пустой базы локально:

```dotenv
ENABLE_DEMO=false
DATA_DIR=./data-clean
```

`NODE_ENV=production` требует HTTPS в `APP_ORIGIN`; для обычного локального HTTP его не устанавливайте. SQLite встроен в Node.js 22 и может выводить предупреждение ExperimentalWarning.

## Что работает

- Регистрация заказчиков и исполнителей, вход, выход; пароли scrypt, серверные сессии в HttpOnly cookie.
- Витрина, поиск без учёта регистра кириллицы, фильтры города/категории, сортировка, избранное в базе.
- Исполнитель публикует предложения с ценой, городом и описанием. Для иллюстраций предусмотрены тематические фотографии.
- Заказчик создаёт открытую заявку. Подходящие по категории/городу исполнители получают уведомления внутри сервиса; логисты — независимо от города отправления.
- Исполнитель оставляет приватный отклик с итоговой ценой, сообщением и сроком. Все отклики видит автор; исполнитель — только свой.
- Заказчик выбирает отклик. В транзакции создаётся один заказ и закрывается выбор по заявке. Цена и условия сохраняются в истории.
- В заказе — контакты сторон, диалог, хронология и статусы. Обновляет работу исполнитель; выполнение/получение подтверждает заказчик.
- Доставка: ссылка на товар, страна, расчёт через отклики, статусы `согласовано → в работе → в пути → прибыло → завершено`.
- Проблема с заказом: описание и фото JPG/PNG/WebP до 5 МБ. Фото доступны только участникам и арбитру.
- Арбитр видит споры в личном кабинете, изучает диалог, фиксирует полный/частичный возврат либо отклонение. При необходимости рейтинг ответственной стороны снижается на 0,2.
- Проверка просроченных доставок раз в минуту; при отсутствии обновления дольше `DELIVERY_STALE_HOURS` создаётся один инцидент.
- Каркас локализации RU/EN/SR для главной навигации, поиска и категорий; пользовательский контент и остальные рабочие экраны MVP — на русском.
- Адаптивная вёрстка. R3F добавляет мерцающие частицы, световые маршруты, шейдерные блики, параллакс и волну от клика на главной; в блоках доставки — объёмная посылка с орбитами. Для touch-устройств снижены плотность частиц, детализация и DPR. При reduced motion сцены статичны; вне экрана и в скрытой вкладке цикл приостанавливается. Без WebGL сохраняются фото и декоративный CSS-макет посылки.

Оплата и возвраты выполняются **между сторонами вне платформы**. В интерфейсе фиксируется решение, деньги не переводятся. Платёжных интеграций и нативных приложений нет, как и предусмотрено MVP. Уведомления реализованы внутри сервиса, без внешней рассылки.

Сценарий «Бизнес-слоты на опережение / реселлинг» в исходном документе не описан; он не реализован. Email-подтверждение, восстановление пароля, Telegram/SMS и загрузка собственных фото предложений — отдельные расширения, в текущий объём не входят.

## Docker + Nginx Proxy Manager

Схема: **Интернет → NPM (HTTPS) → blizu-web:8080 → api:3001 → SQLite volume**. Порты API и БД не публикуются. Только веб-контейнер присоединяется к внешней сети NPM; у API отдельная внутренняя сеть.

1. Создайте общую сеть, если её ещё нет:

   ```bash
   docker network create proxy
   ```

2. Подключите контейнер NPM к этой сети **в его постоянном Compose/стеке**. Не заменяйте существующие сети базы данных NPM; добавьте сеть:

   ```yaml
   services:
     app: # имя вашего сервиса NPM
       networks:
         - default
         - proxy
   networks:
     proxy:
       external: true
       name: proxy
   ```

3. Скопируйте `.env.example` в `.env`. Задайте реальный `APP_ORIGIN` (например `https://blizu.your-domain.me`, **без завершающего слеша**), уникальный пароль арбитра не короче 12 символов и его email. `PROXY_NETWORK` должен совпадать с сетью NPM. Для реального запуска оставьте `ENABLE_DEMO=false`.

4. Соберите и запустите:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

5. В NPM создайте **Proxy Host**:

   | Поле             | Значение                              |
   | ---------------- | ------------------------------------- |
   | Domain Names     | ваш домен из APP_ORIGIN               |
   | Scheme           | `http`                                |
   | Forward Hostname | `blizu-web`                           |
   | Forward Port     | `8080`                                |
   | SSL              | Request a new certificate + Force SSL |
   | Advanced         | `client_max_body_size 6m;`            |

   Домен должен указывать на сервер. Веб-контейнер уже маршрутизирует `/api`, отдельный API-домен не требуется. Не включайте Proxy Cache для API. Веб-сокеты этому MVP не нужны.

Параметры общей сети соответствуют [официальной документации Nginx Proxy Manager](https://nginxproxymanager.com/advanced-config/#best-practice-use-a-docker-network).

## Portainer

Файл **`docker-compose.portainer.yml`** предназначен для **Docker Standalone → Stacks → Web editor**. Он использует готовые образы: Web editor не передаёт локальный build context. Docker Swarm в этом варианте не поддерживается: SQLite использует один постоянный том и один экземпляр API.

### Portainer на том же Docker-хосте

В папке исходников на сервере:

```bash
docker compose build
```

В Portainer создайте стек `blizu`, вставьте содержимое `docker-compose.portainer.yml` и задайте переменные из `.env.example` в **Environment variables**. Отключите принудительное скачивание образов (Re-pull image), если используете локально собранные `blizu-api:latest` и `blizu-web:latest`. Deploy the stack.

### Portainer на другом сервере

Соберите образы для архитектуры сервера и отправьте в свой registry, например:

```bash
docker build --target api -t ghcr.io/YOUR_ORG/blizu-api:1.0.0 .
docker build --target web -t ghcr.io/YOUR_ORG/blizu-web:1.0.0 .
docker push ghcr.io/YOUR_ORG/blizu-api:1.0.0
docker push ghcr.io/YOUR_ORG/blizu-web:1.0.0
```

В стеке задайте `BLIZU_IMAGE_PREFIX=ghcr.io/YOUR_ORG/blizu` и `BLIZU_VERSION=1.0.0`. Для приватного registry предварительно подключите его в Portainer. Образы необходимо собирать для целевой архитектуры, при необходимости через `docker buildx --platform`.

Первый запуск создаёт аккаунт арбитра из `ADMIN_EMAIL`/`ADMIN_PASSWORD`. Изменение этих переменных **не меняет пароль существующего аккаунта**. Обычная регистрация не позволяет получить роль арбитра. Секреты передаются окружением, в клиентскую сборку не попадают.

## Данные и резервные копии

Именованный том **`blizu_data`** содержит `blizu.sqlite`, WAL/SHM и `uploads/`. Он сохраняется при пересоздании контейнеров. Не удаляйте его при обновлении.

Для консистентной резервной копии всей базы и фото временно остановите API и архивируйте том. Пример на Linux-сервере с Docker Compose:

```bash
mkdir -p backups
docker compose stop api
docker run --rm -v blizu_data:/data:ro -v "$PWD/backups:/backup" alpine \
  tar czf /backup/blizu-backup.tar.gz -C /data .
docker compose start api
```

В Portainer можно остановить сервис API через интерфейс и архивировать тот же том. Во время копирования API должен быть остановлен; одиночное копирование `.sqlite` работающего сервиса не учитывает WAL. Для восстановления: остановите API, распакуйте архив в этот том и сохраните владельца UID 1000, затем запустите API. Перед восстановлением сохраните текущий том.

Приложение рассчитано на небольшое сообщество и один экземпляр API. Для нескольких реплик потребуется перенос хранилища в PostgreSQL и общего хранения файлов. В API настроены валидация, rate limits, проверка Origin, контроль ролей и доступа к заказам; это не заменяет настройку сервера и резервного копирования.

## Проверки

```bash
npm run build
npm test
```

Интеграционные тесты используют отдельную временную базу и проверяют регистрацию/роли, приватность, выбор отклика, статусы, переписку, фото спора, решения арбитра и автоматический инцидент. `GET /api/health` проверяет доступность базы; Docker healthcheck использует его.

В среде разработки, где создавался проект, Docker не установлен: сборка TypeScript/React и API-тесты проверяются локально, контейнеры нужно собрать на Docker-хосте.

## Структура

```text
src/                     React: каталог, формы, заявки, заказы, личный кабинет
src/components/Particles.tsx  Жизненный цикл R3F, параллакс, pointer/scroll
src/components/effects/    Шейдеры света, частицы, маршруты и 3D-посылка
shared/types.ts          Общие типы, категории, города, статусы
server/app.ts            API и контроль доступа
server/db.ts             Схема SQLite и демо-данные
server/app.test.ts       Сквозные интеграционные тесты
deploy/nginx.conf        SPA + reverse proxy /api
Dockerfile               Multi-stage targets api / web
docker-compose.yml       Сборка и запуск на Docker-хосте
docker-compose.portainer.yml  Стек из готовых образов
docs/requirements.md     Принятые требования и решения по MVP
```

Фотографии, авторство и лицензии — в `public/credits.html`, лицензия локального Manrope — `public/fonts/OFL.txt`.
